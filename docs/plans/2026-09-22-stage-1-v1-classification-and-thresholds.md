# 阶段 1：V1 分类与触发阈值校准

> 在阶段 0 的运行与数据验收后执行。目标是改善“进入被动消费了吗”的判断，不重写现有状态机。
> 本阶段只处理分类和触发时机；动作效果放到阶段 2。

## 已有实现与真实缺口

| 已有代码 | 已做到 | 仍需回答 |

特别注意：早期 Brotato 漏判促成了**已实现**的全屏提权。V1 要实测这条规则是否真正解决漏判及其误报代价，不能把“新增全屏识别”再次列为开发任务。

## 任务 1.1：建立可复查的标注与规则版本

- **输入：** 阶段 0 的可信跨天记录、`evaluations` 的 `skipped/data_status/entries_minutes/fullscreen_state/gate_trace`，以及仅在 Screenpipe 留存期内按需回查的 `app/title/url`。
- **工作：** 抽取不同日期、时段和场景的代表性窗口，由人标注“是否被动消费”“当时是否适合提醒”“原因”。把重叠的五分钟评估窗口合并为同一次消费事件，统计事件级漏判、误报和首次提醒延迟；保留逐轮结果供定位。标注有争议时保留“不确定”，不强行归类。
- **数据边界：** 标注记录只保存必要的类别、时间、人工结论与匿名样本 ID；原始标题和 URL 只在本机临时查看，不写入仓库或 StateSense 数据库。
- **代码任务：** 若要跨配置版本做自动比较，在 `store/schema.sql`、`store/db.py` 与 `Scheduler` 中新增规则版本标识，旧行留 `NULL`，升级 `SCHEMA_VERSION`。版本至少能区分分类清单、阈值和全屏规则的改变；在实现前确定稳定生成方式。只记录可追溯标识，不复制屏幕文本。
- **验收：** 任一图表都能指出样本日期、规则版本、有效窗口数和消费事件数；旧行“版本未知”与新版本不混算。

## 任务 1.2：定位分类与全屏信号问题

- **先用现成能力：** `--report --views 1,2,5` 和必要时的 `--from-screenpipe`，配合 `--trace` 查闸门。
- **工作：** 对人工标记的漏判逐一归因：正则未命中、Screenpipe 明细缺失、全屏状态未知、全屏状态 2 误报、或场景本身不是被动消费。分别列出每类数量和代表性案例。检查 WORK/GRAY 与娱乐正则的优先级是否造成误判；GRAY 仍独立计数，是否重分类由标注数据决定。
- **实施位置：** 纯分类规则优先修改 `config/config.example.toml` 的示例清单及用户本地配置；确有证据说明优先级或全屏提权语义错误时才改 `state/taxonomy.py`、`state/engine.py` 或 `perception.py`。更改 `effective_entertainment_minutes` 时同步检查回执路径，因为它是唯一娱乐分钟公式。
- **验收：** 每项改动列出原始问题、修复后改善的事件数和新增误报事件数；全屏终端不因一次状态 2 就被无证据地判成游戏。

## 任务 1.3：在固定分类版本下比较阈值

- **现成边界：** `config.py` 已校验 20 ≤ 40 ≤ 55 ≤ 60、`ratio_min` 非空且合法；`gates.py` 已给每条闸门留下值和阈值。
- **工作：** 固定阶段 1.2 的分类结果，在同一批标注事件上比较候选 `watch_minutes`、`passive_minutes`、`high_risk_minutes` 和 `ratio_min`。分别展示首次可提醒时间、漏判事件、误报事件、每天预计弹窗次数，以及被 `ratio_min` 单独挡住的已达状态事件。现有库可重算阈值条件，但分类候选必须重新取得原始条目，不能从 `ent_minutes` 反推出标题或 URL。
- **实现方式：** 先做只读、离线的纯函数比较；如现有 `report/queries.py` 足够就不新增运行功能。要保留工具时，把分析留在 `report/` 的只读边界内，SQL 仍由 `store/` 提供。候选规则不得直接修改生产配置。
- **验收：** 给出一组建议配置或明确保留现值，说明选择依据和样本不足之处。阈值须保持 HIGH_RISK 可达，且不得绕过 `state_min`。

## 任务 1.4：小步上线与回归

一次只上线一组有依据的规则变更，记录生效时间与规则版本；用新增的针对性样本覆盖误报/漏判边界，运行 `uv run pytest -q` 和 `--replay all`，再观察跨天报告。若引入额外弹窗或真实漏判变多，回到上一个已记录的配置版本。

## 阶段出口

形成稳定的分类与阈值基线：人工标注样本、事件级对照、规则版本、实际提醒频率和已知误报均可复查。没有这些证据时，阶段 2 不给动作排名。
