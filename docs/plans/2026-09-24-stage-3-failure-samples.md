# 阶段 3.1：失败样本集与目标指标

> 对应计划 `2026-09-22-stage-3-v2-llm.md` 任务 3.1。完成条件是「固定、可复查
> 且脱敏的评估样本和明确的目标指标」。样本全部来自阶段 1 的合成语料
> （`tests/test_stage1_event_calibration.py`），**脱敏是构造性的**——没有
> 任何真实标题、URL 或使用记录；基线读数钉死在
> `tests/test_stage3_failure_samples.py`（9 条，2026-09-24 实测通过）。
> 合成数据不代表真实分布；本文档给模型定的目标是对**口径性质**的改善目标，
> 不是对用户行为的预测。

## 一、失败类：基线读数、目标指标、护栏

规则基线 = 现值（20/40/55，ratio_min 0.75）。合成日读数：
真事件 2、系统事件 1、漏判 2、误报 1、首次可判 (None, None)、弹窗 2——
**全部弹窗都落在唯一一个误报事件上**。现状不是「提醒太多」，是「提醒的对象错了」。

| 类 | 场景（合成日） | 规则基线 | 模型目标指标 | 护栏（修复不得破坏） |
| --- | --- | --- | --- | --- |
| F1 | 30 分钟刷视频：ent 峰值 30 < passive 40 | 漏判 1，首判 None | 该类漏判 → 0 | 弹窗数不增；误报不增 |
| F2 | 90 分钟窗口化游戏（Brotato，清单未命中）：ent 恒 0 | 漏判 1；任何阈值候选救不回（阶段 1 已钉死，口径性质） | 首次可判 None → 事件内 40 分钟级 | 全屏文档类不因此新增候选 |
| F3 | 90 分钟全屏读文档：OTHER 满窗被提权 → ent=60 → HIGH_RISK | 误报 1；两次弹窗全在它身上 | 误报 → 0 | **全屏真游戏必须仍可达 PASSIVE 以上**（护栏语料变体：40 分钟够 PASSIVE、55 分钟 HIGH_RISK） |
| F4 | 状态达标但被 ratio_min 单独挡下 | 现值 0（压低阈值后才出现，eager 下 1） | **不设模型目标**——模型不得绕闸门（spec 边界） | 可见性已有：`ratio_blocked_*` 计数 + 报表 |

## 二、输入可分性：影子白名单下模型能看到什么（本轮关键发现）

影子输入是六个原子量（`shadow/models.py::ALLOWED_FIELDS`）；`other` 不在
白名单里但可由 `total − 其余三项` 导出。用「指纹」`(ent, gray, work, total)`
表示一轮的完整可见信息（取值走生产公式 `classify`，ent 含提权）：

| 类 | 指纹（满窗轮） | 与谁同点 | 模型可及性 |
| --- | --- | --- | --- |
| F1 | (30, 0, 30, 60) | 任意「半娱乐半工作」混合窗 | **可及**；上限 = 一个更优的阈值函数（它知道的规则也知道） |
| F2 | (0, 0, 0, 60) | **任何未命中清单的满窗应用**（如用没进清单的 Word 写报告） | 部分可及：增益本质是对「满窗未归类」的先验，歧义随候选同行 |
| F3 | (60, 0, 0, 60) | **真全屏游戏**（提权后指纹完全相同） | **v1 输入契约下结构性不可及**——任何模型都分不清全屏文档与全屏游戏 |
| F4 | — | — | 不适用（闸门语义，非分类） |

三条直接推论（已写进测试）：

1. **F3 在当前输入契约下不该跑影子目标**。要让模型参与 F3，先得改输入契约
   （例如把 `fullscreen_state` 原始值加进白名单——它曾被刻意排除，理由见
   `shadow/models.py::DEFERRED_FIELDS`；要不要翻案是 3.4 判定规格的事，
   本文档只把「不可及」这个事实钉住）。
2. **F2 的候选必须连同歧义一起采信**。模型把「满窗未归类」读作「可能在玩」
   时，对未命中清单的写作应用同样成立；3.4 判定规格若采信这类候选，
   应记为低置信并单独计数。
3. **F1 的增益上限是更好的阈值**。影子对比若显示 F1 类「改善」，解读必须
   是「模型学到了非线性阈值」，而不是「模型看出了规则看不到的证据」——
   输入里没有额外的证据可看。

## 三、规则先行的处置（本轮不改任何判定规则）

计划要求「能通过现有配置或纯规则修复的，先解决」。逐类结论：

| 类 | 纯规则修复选项 | 处置 |
| --- | --- | --- |
| F1 | 阈值降到 25/25/50（eager） | **不采纳**（阶段 1 已裁决：救 1 漏判，代价 +3 弹窗、其中 2 次余波） |
| F2 | 把游戏名加进分类清单 | **不采纳**：按游戏名维护清单没有普适性（`perception.py` 的立项理由） |
| F3 | a) 文档阅读器加进 WORK 清单；b) 纯提权封顶 PASSIVE；c) 接受现状 + 影子观测 | **推荐 c**；a 只救清单内应用（浏览器 PDF 走 chrome 未命中 → OTHER，照旧误报），b 不消弹窗只降档（PASSIVE 同样投递）——两者都动 F-游戏识别的地基（BUSY=2 是实测决定） |

F3 的「推荐 c」需要一句诚实的补充：**本机没有真实运行数据，文档误报的真实
频率未知**。影子基础设施已就位（schema v8、视图 9、影子剧本），正确的顺序
是让 F3 在真实影子样本里先亮出来，再决定要不要动清单或提权语义。
护栏已钉死：任何修复不得把全屏真游戏压到 PASSIVE 以下。

因此**本轮零判定规则变更，`rulebook.rule_version` 不变**——影子对比的基线
没有移动。

## 四、措辞表达需求（任务 3.1 后半，喂 3.3）

阶段 2 的回执口径没有留下「措辞不够用」的直接证据，以下需求来自模板
结构本身（`intervention/wording.py`）的缺口盘点：

- **W1 回执上下文缺失**：模板不知道「20 分钟前刚提醒过、用户没理」，
  写不出跟进语气。需要的结构化字段：当前事件内已有提醒次数、最近一次
  回执状态（continued / disengaged）——均非私密，可进传输契约。
- **W2 动作语境割裂**：`action.text` 由动作池轮转产生，模板只能整句拼接
  （「{动作}？」）。候选文案应能围绕动作写完整句子。
- **W3 top_label 隐私边界**：现模板内嵌窗口标题——本机弹窗可以，
  远端模型不可见。接口需拆出**可传输字段**：分类类别名（ENTERTAINMENT /
  WORK / GRAY / OTHER，已在代码中存在、非私密）、分钟数、状态、动作。
  这是 3.3 的前置接口改动。
- **W4 凌晨语境已有**：`late_night` 在 verdict 里，模板已区分——不构成新需求。
