# 阶段 3：V2 验证 LLM 的增量价值

> 阶段 1 已有可信分类基线、阶段 2 已有真实干预效果口径后再进入。先离线、再影子运行，最后才考虑影响真实投递。

## 现有接入点与限制

| 现有代码 | 能复用什么 | 缺什么 |
| --- | --- | --- |
| `intervention/wording.py::Wording` / `TemplateWording` | `Scheduler` 已通过接口注入文案生成器，可先试个性化措辞而不改闸门 | 当前文案接口接收 `top_label`（窗口标题）；若接远端模型，必须先决定是否允许发送这一字段 |
| `state/engine.py::classify` | 状态计算是纯函数，时间与信号由调用方注入；确定性规则可作为基线 | 没有模型信号契约，也没有模型分歧的持久化或复盘视图 |
| `intervention/decider.py` / `gates.py` | state_min、ratio_min、cooldown、daily_cap 等规则已经稳定 | 模型绝不能直接跳过这些闸门或自行投递 |
| `replay/` 与 `report/` | 可对新增信号做端到端剧本与只读观测 | 现有五个剧本没有模型超时、畸形输出、分歧等场景 |

当前 `pyproject.toml` 的运行期依赖为空；引入模型之前应先确定部署方式与调用边界，不为了“加 LLM”先引入无目标的 SDK。

## 任务 3.1：把问题限定到具体失败样本

从阶段 1 标注中挑出分类清单、全屏规则和阈值仍处理不好的模糊场景，列明规则基线的事件级漏判、误报和首次提醒时间。从阶段 2 挑出模板措辞无法覆盖的具体表达需求。每类问题单独评估；能通过现有配置或纯规则修复的，先用现有能力解决。

**完成条件：** 有固定、可复查且脱敏的评估样本和明确的目标指标，而不是只写“模型更智能”。

## 任务 3.2：确定隐私与模型输入契约

- 明确本地模型或远端服务、允许的结构化输入、保留期限、延迟和调用成本。第一轮以聚合分钟数、状态、闸门结果、动作 ID 这类既有结构化数据为候选；窗口标题、URL 和屏幕正文可能含私人内容，不自动送到远端。
- `ActivityReader` 继续是唯一知道 Screenpipe 的模块，不增加 OCR/屏幕正文采集；任何从屏幕来的文字都作为不可信证据，不得作为系统指令。
- 模型输出定义为有限枚举与结构化理由，例如“候选状态/不确定/拒答”，并记录模型和提示版本。超时、非法输出或证据不足时，本轮不新增干预。
- 如果要保存影子结果，在 `store/db.py` 中新增独立的可空事实并增量迁移；旧行留 `NULL`，不得把“当时没有模型”写成“模型判定为否”。`report/` 只读取和聚合，不写库。

**完成条件：** 评审者能列出模型实际看到了哪些字段，以及哪些字段不会离开本机。

## 任务 3.3：先评估文案

在 `Wording` 接口下实现候选文案生成器，保持 `Scheduler` 的判定和闸门结果原样。离线比较模板与候选文案的长度、清晰度、重复性、冒犯或泄露风险，以及生成时间。远端调用不得直接使用当前 `top_label` 参数；必要时先把接口拆成明确允许传输的结构化字段。只有样本证明有收益，才在可关闭的真实运行配置中启用。

**完成条件：** 同一批干预机会下触发次数与动作 ID 和规则基线一致；变化仅限文案，失败时不产生额外弹窗。

## 任务 3.4：模糊状态先影子运行

- 在状态判定之前由调用方生成一个显式的模型候选信号；`state/engine.py` 保持纯函数，不在内部读网络、时钟或数据库。影子模式只记录候选与规则的分歧，不改变真实状态和 `Decision`。
- 用阶段 1 的人工真值按消费事件比较规则与模型：漏判、误报、首次可提醒时间；另列延迟、费用、拒答率和输入数据覆盖度。不能只挑模型正确的案例。
- 如影子模式有稳定增益，再写一个明确的判定规格，规定模型信号只能作用于哪些模糊窗口、如何与既有娱乐分钟及全屏信号组合。新增回放场景必须覆盖无数据、拒答、超时、错误输出与规则冲突，且 `state_min` 和其余闸门仍是投递必经路径。

**完成条件：** 在固定样本与随后真实影子样本上均显示可复查的收益，没有不可接受的额外打扰或隐私暴露。

## 任务 3.5：有限上线与退出条件

只对阶段 3.4 指定的场景启用，记录模型版本、规则版本与最终决策来源，使 `--report` 能把模型参与和纯规则结果分开。对照实际提醒次数、用户回应、行为回执和误报；任何收益不稳定、成本超限或输入边界不清的情形都停止扩量，维持已验证的规则方案。

## 阶段出口

LLM 的具体收益、代价和数据流有证据支持，且真实投递仍由现有状态、闸门、动作和回执链路统一管理。若 V1 数据不足，本阶段停在离线评估，不接入真实干预。
